# Domain Docs

1. Before you explore or edit code, read `GLOSSARY.md` at the repo root and `docs/architecture.md`. Read any ADR in `docs/adr/` that touches the area under change.
2. Name types, members, issue titles and tests with the terms in `GLOSSARY.md`.
3. When WhatsApp or whatsmeow has a name for a concept, use that name for the term.
4. Never use a synonym listed under _Avoid_ in `GLOSSARY.md`.
5. `docs/architecture.md` holds the decisions whisker starts from. Write an ADR in `docs/adr/` only when a change reverses or replaces one of them. Name the decision it changes.
